# Temario · Claude Code desde cero

Proyecto práctico: **VisitasAPI** (.NET 8, Clean Architecture). Ritmo: L-V 40 min, sábado 20, domingo 15 (aprox. 245 min por semana).
Regla de oro de todo el curso: **predecir, revisar el diff, explicar**.

| Slug | Semana | Título | Objetivo (al terminar podrás...) |
| --- | --- | --- | --- |
| 00-como-usar | - | Cómo usar este curso | Entender el ritmo, la regla de oro y preparar tu entorno (Windows, .NET 8, Git, cuenta de Claude). |
| 01-introduccion | 1 | Introducción a Claude Code | Instalar Claude Code, entender cómo trabaja y crear el esqueleto de VisitasAPI. |
| 02-claude-md | 2 | CLAUDE.md y contexto | Escribir un CLAUDE.md útil y manejar el contexto para que Claude siga las reglas de tu proyecto. |
| 03-flujo-de-trabajo | 3 | Explorar, planificar, codificar | Usar modo plan y revisar diffs para construir la primera funcionalidad (registro de visitas) sin perder el control. |
| 04-pruebas-y-depuracion | 4 | Pruebas y depuración con IA | Generar y revisar pruebas xUnit y depurar errores explicando la causa, no solo aplicando el arreglo. |
| 05-permisos-y-seguridad | 5 | Permisos, settings y seguridad | Configurar settings.json y permisos, y evitar exponer secretos o ejecutar comandos peligrosos. |
| 06-mcp | 6 | MCP: conectar herramientas | Conectar Claude a documentación de .NET, GitHub y una base de datos mediante MCP. |
| 07-subagentes | 7 | Subagentes | Crear subagentes especializados (revisor, pruebas) y delegarles tareas en VisitasAPI. |
| 08-skills-y-comandos | 8 | Skills y comandos propios | Empaquetar flujos repetibles como skills y comandos personalizados. |
| 09-hooks-y-plugins | 9 | Hooks y automatización | Automatizar validaciones (formato, build, pruebas) con hooks y entender cómo se empaqueta un plugin. |
| 10-proyecto-final | 10 | Proyecto final: VisitasAPI completo | Entregar VisitasAPI en tu GitHub con historial limpio, pruebas, README y configuración de Claude Code. |

Notas:
- Los 3 módulos 7-9 y el proyecto final admiten material extra del Kit Premium (campo `premium` del esquema), nunca el contenido base.
- Cada módulo incluye: teoría, laboratorio, reto, preguntas de repaso y fuentes oficiales enlazadas (contenido propio, sin copiar la documentación).
- Orden sujeto a ajuste por el autor; el slug y el número no deben cambiar una vez publicados (las URLs se comparten en redes).
